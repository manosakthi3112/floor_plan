# Plan: Doors, Floors, Windows, Stairs — 3D editor feature pass

## What you asked for
1. **Doors** with real open/close **swing animation**
2. **Walls** rendering (already works — leaving as-is)
3. **Floor coloring** — both **global** (all floors at once) and **per-room** (per-room already exists)
4. **Windows** (already render — small visual polish only)
5. **Detect stairs** from the floor plan image + render as **realistic 3D stairs**

I'm building **all five**. Default choices I'm taking (since the clarifying questions weren't answered): stairs = **detect + manual tool, straight-run shape**; door trigger = **click door in 3D**. These are the pragmatic, lowest-risk options and match how doors/windows already work.

## Architecture facts that shape the plan (from exploration)
- 3D flow: `meshBuilder.ts` produces `MeshDescriptor[]` → `useFloorPlanSync` resolves colors → `Viewport3D` filters by `type` and instantiates component meshes (`WallMesh`, `FloorMesh`, `OpeningFrame`, `OpeningGlass`).
- **Two mirrored type files** must stay in sync: `apps/web/src/types/floorPlan.ts` and `packages/shared-types/src/floor-plan-graph.ts`.
- Store (`floorPlanStore.ts`) uses zundo; **only `graph` + `roomStyles` are undoable** (the `partialize` whitelist at L134). New undoable state must be added there.
- Doors today are a **frame + flat glass pane** — there's no swingable leaf. `Opening.swingDirection` exists but is unused in 3D.
- **No stairs exist anywhere** in the repo — fully greenfield.
- Python parsing emits snake_case dicts → orchestrator hand-builds camelCase; schema uses `list[dict]` so keys pass through `model_dump()`.

## Part A — Door swing animation (click-to-open in 3D)

### A1. New 3D component: `DoorLeaf.tsx`
A swingable door panel. Geometry: a thin box sized to the opening (`width × height`), translated so its **left edge** sits at the hinge. Wrapped in a pivot `<group>` whose Y-rotation animates 0 → ±90°. Uses `@react-three/fiber`'s `useFrame` to lerp `rotation.y` toward the target each frame (smooth easing). Clicking the mesh toggles `open` state via an `onClick` handler (r3f pointer events). Hinge side comes from `opening.swingDirection` ('left'/'right'); closed leaf sits inside the opening; opening swings inward.

### A2. Store: door-open state (transient, NOT undoable)
Add to `floorPlanStore.ts`: `doorOpenState: Record<string, boolean>` + `toggleDoor(openingId)` action. Deliberately **exclude from `partialize`** — animation/play state shouldn't be undone. Doors default closed.

### A3. `meshBuilder.ts`: emit a `door_leaf` descriptor
Extend `MeshDescriptor.type` with `'door_leaf'`. In `buildFrameMesh`, when the opening is a door, build a leaf descriptor: geometry = `BoxGeometry(opening.width, opening.height, 3)` translated so geometry origin = hinge edge; carry `openingId` + the hinge info. The frame stays; the old "door_glass" pane is replaced by the leaf for doors (windows keep their glass).

### A4. `Viewport3D.tsx`: render door leaves
Filter `type === 'door_leaf'` and render via `<DoorLeaf>`, passing `openingId` + reading `doorOpenState` from the store to drive each leaf's target angle.

## Part B — Global floor color (+ keep per-room)

### B1. Store
Add `globalFloorColor: string | null` + `setGlobalFloorColor(color)` to `floorPlanStore`. **Add to `partialize`** (it's a design decision, should undo). `null` = "no global override".

## Part D — Stairs (detect from image + 3D render)

### D1. Types: `Stair` interface (both type files)
```ts
interface Stair {
  id: string;
  start: Point;        // bottom of staircase
  end: Point;          // top of staircase
  width: number;       // mm
  numSteps: number;
  stepHeight: number;  // mm (riser)
  direction: 'up' | 'down';
  roomId?: string;
}
```
Add `stairs: Stair[]` to `FloorPlanGraph` in **both** type files. Add `addStair`/`updateStair`/`deleteStair` store actions + seed `stairs: []` in `emptyGraph()` + add to `partialize`.

### D2. Python: `stair_detector.py` (new processor)
Detects stairs by recognizing the **parallel-line stripe pattern** typical of stair symbols in floor plans: in the wall-free binary mask, find clusters of evenly-spaced parallel lines (≥4 parallel segments with uniform spacing) inside a room. Returns `Stair` dicts (start/end of the run, width, estimated step count from the line count). Wired into `orchestrator.py` after room extraction (so we can attach `roomId`). Auto-detection is best-effort; manual placement is the reliable path.

### D3. 2D: `'addStair'` tool + `StairSymbol` rendering
Add `'addStair'` to `ToolType` + the toolbar (icon `≣`). In `FloorPlanCanvas`, handle `addStair` like the door tool: click-drag from start→end inside a room to define the run; create a `Stair` with default step counts. Render a `StairSymbol` (striped rectangle showing direction).

### D4. `meshBuilder.ts`: `buildStairMesh`
For each stair, build a series of `BoxGeometry` steps along the run direction, each step a box `(width, stepHeight, stepDepth)` rising cumulatively — a realistic straight-run staircase. New `MeshDescriptor.type: 'stair'`. Rendered via a `StairMesh` component in `Viewport3D`.

## Build order (so each step is independently testable)
1. **Types + store** (stairs, door state, global floor color) — foundation, no visual change yet.

4. **Stairs 3D + manual tool** (D1, D3, D4) — see a staircase render from a manual placement.
5. **Stair detection** (D2) — wire Python detection last; manual tool guarantees stairs work even if detection misses.
6. **Window polish** (C) — last, lowest priority.

## Risk / notes
- **r3f animation**: `useFrame` lerp is the standard, low-risk approach; no physics lib needed.
- **Stair detection imperfection**: realistic floor plans vary hugely; that's why the manual tool ships alongside — detection is an enhancement, not the only path (consistent with how doors/windows already offer manual tools).
- **zundo `partialize`**: I'm being deliberate about what's undoable (graph/styles/global color = yes; door-open animation state = no).
- Out of scope: multi-story level linking, spiral/L/U stairs, GLB animation baking — these can follow if you want them.
